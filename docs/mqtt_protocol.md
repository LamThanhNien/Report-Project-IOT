# MQTT Protocol

## Topic Convention

All device topics use the base pattern `devices/{device_id}/...` where `device_id` is the registered `device_uid` (e.g., `esp32-demo-001`).

### Current Topics (v2)

| Topic | Direction | QoS | Description |
|-------|-----------|-----|-------------|
| `devices/{device_id}/telemetry` | Device → Backend | 1 | Sensor readings, uptime, RSSI, heap |
| `devices/{device_id}/telemetry/ch_v{pin}` | Device → Backend | 0 | Raw string telemetry value for Virtual Pin |
| `devices/{device_id}/status` | Device → Backend | 1 | Online/offline status, boot messages |
| `devices/{device_id}/heartbeat` | Device → Backend | 1 | Keepalive signal (presence detection) |
| `devices/{device_id}/events` | Device → Backend | 1 | Command results, alerts, custom events |
| `devices/{device_id}/commands` | Backend → Device | 1 | Remote commands (relay control, reboot) |
| `devices/{device_id}/commands/ch_v{pin}` | Backend → Device | 1 | Raw string command payload for Virtual Pin |
| `devices/{device_id}/ota` | Backend → Device | 1 | OTA firmware update instructions |
| `devices/{device_id}/ota/status` | Device → Backend | 1 | OTA progress and completion reports |

### Legacy Topics (backward compatible)

| Topic | Direction | Description |
|-------|-----------|-------------|
| `aifom/devices/{device_id}/telemetry` | Device → Backend | Legacy telemetry |
| `aifom/devices/{device_id}/status` | Device → Backend | Legacy status |
| `aifom/devices/{device_id}/heartbeat` | Device → Backend | Legacy heartbeat |
| `aifom/devices/{device_id}/ota/result` | Device → Backend | Legacy OTA result |

## Payload Schemas

### Telemetry

```json
{
  "device_id": "esp32-demo-001",
  "firmware_version": "1.0.0",
  "uptime_ms": 123456,
  "rssi": -55,
  "free_heap": 120000,
  "temperature": 30.5,
  "humidity": 70.2,
  "light": 420.0,
  "soil_moisture": 44.1,
  "battery_level": 3.92,
  "relay_1": true,
  "relay_2": false,
  "timestamp": "2026-05-24T12:34:56Z"
}
```

### Status

```json
{
  "device_id": "esp32-demo-001",
  "status": "online",
  "firmware_version": "1.0.0",
  "ip": "192.168.1.50",
  "rssi": -55,
  "uptime_ms": 123456,
  "free_heap": 120000,
  "message": "boot complete",
  "timestamp": "2026-05-24T12:34:56Z"
}
```

**Status values:** `online`, `offline`, `unknown`

### Heartbeat

```json
{
  "device_id": "esp32-demo-001",
  "timestamp": "2026-05-24T12:34:56Z"
}
```

Heartbeats are sent periodically (default: every 30s). The backend's `DevicePresenceMonitor` marks devices offline if no heartbeat is received within `offline_timeout_seconds` (default: 60s, configurable per device, range: 10–600s).

### Command

Backend publishes to `devices/{device_id}/commands`:

```json
{
  "command_id": "cmd_123",
  "type": "set_output",
  "target": "relay_1",
  "value": true,
  "params": {
    "target": "relay_1",
    "value": true
  }
}
```

Device publishes command result to `devices/{device_id}/events`:

```json
{
  "event": "command_result",
  "command_id": "cmd_123",
  "device_id": "esp32-demo-001",
  "type": "set_output",
  "target": "relay_1",
  "status": "success",
  "message": "relay_1 set to true",
  "relay_1": true,
  "relay_2": false
}
```

### OTA Update

Backend publishes to `devices/{device_id}/ota`:

```json
{
  "job_id": "ota_123",
  "firmware_version_id": "fw_123",
  "firmware_version": "1.0.1",
  "firmware_url": "http://aifom.local:8000/api/v1/firmware/fw_123/download",
  "checksum": "sha256_hex...",
  "force": false
}
```

Device publishes OTA status to `devices/{device_id}/ota/status`:

```json
{
  "job_id": "ota_123",
  "device_id": "esp32-demo-001",
  "status": "downloading",
  "progress": 45,
  "firmware_version": "1.0.1",
  "message": "Downloading firmware"
}
```

**OTA status values:** `accepted`, `downloading`, `flashing`, `rebooting`, `success`, `failed`

## Authentication & Authorization

### Authentication

MQTT requires username/password authentication. Two users are configured:

| User | Purpose | Credentials |
|------|---------|-------------|
| `aifom_backend` | Backend subscriber | `MQTT_ADMIN_USER` / `MQTT_ADMIN_PASSWORD` |
| `aifom_device` | Device clients | `MQTT_DEVICE_USER` / `MQTT_DEVICE_PASSWORD` |

Password file is auto-generated by `infrastructure/mosquitto/docker-entrypoint.sh` from environment variables.

### ACL (Access Control List)

The Mosquitto ACL file (`infrastructure/mosquitto/config/acl`) enforces per-topic authorization:

**Backend (`aifom_backend`):**
- Subscribe: all device telemetry, status, heartbeat, events, OTA status topics
- Publish: `devices/+/commands`, `devices/+/ota`

**Device (`aifom_device`):**
- Publish: `devices/+/telemetry`, `devices/+/status`, `devices/+/heartbeat`, `devices/+/events`, `devices/+/ota/status`
- Subscribe: `devices/+/commands`, `devices/+/devices/+/ota`

**Pattern-based ACL** (for per-device isolation when using unique client IDs):
- `pattern read devices/%u/commands`
- `pattern write devices/%u/telemetry`

> **Note:** With shared `aifom_device` credentials, device-level topic isolation is enforced at the application layer via `TenantDeviceMapping`, not at the MQTT ACL level. For true per-device MQTT isolation, provision unique credentials per device.

## Device Discovery

Devices discover the MQTT broker via **mDNS** (service type `_mqtt._tcp`). Do not hardcode the broker IP in firmware.

**mDNS flow:**
1. ESP32 boots and connects to WiFi
2. ESP32 queries mDNS for `_mqtt._tcp.local.` on `aifom.local`
3. mDNS returns broker IP and port
4. ESP32 connects with `MQTT_DEVICE_USER` / `MQTT_DEVICE_PASSWORD`

**Environment variables for physical devices:**
```
DEVICE_MQTT_HOST=aifom.local
DEVICE_MQTT_PORT=1883
```
